# My private SDK1 interface bridge over SDK2

I record this as a historical implementation candidate outside Core, the stable Win32 copy and the installed client. I do not publish or redistribute the SDK through it. I implemented all 30 virtual SDK1 methods and kept the vendor interfaces in separate translation units. I have SDK1 consumers include `LegacyVideo21Adapter.h`; only `Backend21.cpp` and my sound implementation include the namespaced SDK2 header. I keep both vendor interfaces out of the neutral `Backend21.h`.

## How I retain genuine bindings and ownership

I use `CreateLegacyVideo21(DWORD,void**)` as a typed internal C++ factory, not an incompatible cast of the DLL's `CreateBandiVideo2` export. I verify an absolute `bdvid64.dll` path and SHA-256 through a read-only file handle before loading with DLL-directory/System32 dependency search. I create the real SDK2 object with its actual four-argument factory, pass independently reference-counted reader/sound interfaces and release the SDK before unloading the module. I allow identical policy configuration idempotently and refuse a policy change with a live decoder.

I return the actual SDK result from `Verify`. I refuse Open unless that same object received `S_OK`; I never invent successful registration. In my authorized real harness I read unchanged existing product arguments only in memory/anonymous stdin, redact unexpected output before logs and never put arguments on command lines, in receipts or in generated source. I do not treat successful Verify as legal redistribution entitlement.

I use a real read-only HANDLE for file playback. I borrow custom `IBandiVideoSource`, without deleting it or inventing COM reference counting. I require its owner to retain it until synchronous Close finishes or queued Close actually completes. I contain exceptions and invalid read counts in reader callbacks before returning across the vendor ABI. I have no game caller currently using the custom-source overload, but I compile and test its real interface.

I run every SDK call on one bridge worker. My public asynchronous methods admit bounded FIFO commands and return admission results, not fabricated SDK completion. I found an actual ordering failure when I also requested SDK-native asynchronous Open: a subsequent successful Seek could be superseded by the SDK's source reset, leaving playback at the beginning. I now perform SDK Open synchronously inside my already-asynchronous worker. In the same real harness I went from EOF failure with frames at 0–7.96 seconds to final-frame playback and one EOF. I retain OpenAsync→SeekAsync→PlayAsync as an actual nonblocking caller sequence.

I check queue allocation/capacity before changing cancellation state. I invalidate prior operations on Stop/Close/new Open. I reject reentrant synchronous source-callback calls rather than deadlocking, while permitting asynchronous cancellation. I drain cancelled promises and join the worker during shutdown. I cannot safely force-terminate a blocked codec call inside the product; I use an external 35-second own-process watchdog in the isolated harness instead.

## How I handle frames, timing and notifications

I have SDK2 fill bridge-owned X8R8G8B8 CPU storage and check dimensions, pitch, total storage and integer limits. I manually convert to the three actual SDK1 formats: X8R8G8B8, A8R8G8B8 and R5G6B5. I do not invent a legacy RGB24 format or use SDK2's observed all-black RGB24 path.

I permit only the creating render thread to upload/return D3D9 resources. In this implementation I feed a DEFAULT-pool texture from SYSTEMMEM staging through UpdateTexture. I use a real top-down DIB/HBITMAP for the memory context. I bound retained resources with four frame slots and cannot overwrite/free a slot with outstanding leases. I pair borrowed textures with AddRef/Release, reject double/unknown releases and refuse object destruction/device reset with outstanding borrows. I retire frames on Close without invalidating an existing lease. I free unborrowed DEFAULT resources in BeforeDeviceReset and permit recreation from retained CPU content in AfterDeviceReset. I observed MANAGED textures from the old SDK, but this bridge deliberately uses DEFAULT with explicit reset hooks at this stage. I require consumer integration of those hooks; matching the exposed format does not make the pools identical. I check callback-admitted Stop/Close against the captured epoch after decode and before publication/lease, preventing reintroduction of a cancelled CPU frame. I preserve the normal lifetime of already-issued leases.

I established identical RGB/BGRA and alpha 255 for MEMORYBUFFER X8/A8 after SetAlpha(0/128/255) through independent fresh-frame SDK1 measurements. In six further real SDK1 D3D9 cases I received X8 textures even when requesting A8, with unchanged sampled RGB/BGRA and alpha 255. In V2 I therefore retain X8/A255 for both requested 32-bit formats and validate/remember SetAlpha without inventing a pixel modification absent from the measured legacy interface. I keep the requested format flag separate from actual texture format. I limit this to exposed frames, not unseen SDK-internal or host screen composition.

I also measured negative finite SDK1 frame/time conversion and truncation toward zero, which I preserve within INT range. I use checked nonnegative seconds→100 ns for Seek, including the exclusive 2^63 bound because MSVC long double is double-sized. I derive CurrentRenderTime from the delivered frame timestamp and playback time from the real sound clock plus seek offset, falling back to the delivered frame only when an audio clock is legitimately absent. Because SDK2 does not expose SDK1 ErrorFrames, I explicitly expose bridge decode failures rather than invent an SDK counter.

I implement repeat with real Seek(0)+Play, suppressing terminal EOF. I retain SDK1 WPARAM=instance for EOF and WPARAM=actual completion HRESULT for OPENED. I use LPARAM as a bridge-only, instance-unique operation cookie and require the host's corresponding ConsumeCurrent* hook to reject stale/duplicate notifications. I publish notification state before PostMessage so an immediately scheduled UI consumer cannot lose a valid event. I claim no SDK2 notification ABI.

## How I distinguish qualified observations from remaining integration

I use the actual legacy class and SDK1 header, real GDI/threads/futures/PostMessage and an explicitly fake neutral decoder in my native facade contract executable. I exercise all 30 methods, queues, reentrancy, leases, conversions and notification ownership. In a separate executable I use exact extracted Reader/HashFile/ValidPolicy bodies, the real SDK2 interface, read-only file APIs and CNG without loading the SDK.

I compile production Legacy/Backend/SoundV2 TUs in the real bridge executable. I passed four AVI cases with NULL sound and one logo case with real DirectSound muted before Play. I create only an owned hidden HWND and D3D9 device in each, observe nonzero RGB after texture upload/offscreen draw/readback and test Pause/Resume, Stop/Close, Seek, leases, actual Reset, queued reopen/seek/play and exactly-once terminal EOF. I establish that harness path, not game UI behavior, physical audio output, audiovisual synchronization, every format/codec, arbitrary seeks or full device-loss recovery.

I still need to complete Core integration at this stage: typed factory/policy setup, external SDK2-header location, exact module placement, consumer notification filtering and frame-release RAII. In particular, I require CNtlMovie's pre-existing GetSurfaceLevel-failure path to return its borrowed frame and its independently owned render texture to release at teardown. I do not call integration complete if it returns success while silently skipping those lifetimes. I changed no Core, installed runtime, game, server, SQL, codec registration or operating-system setting through this candidate.

## How I record V2 review and the measured compatibility update

I found a missing generation check in the first independent bridge review when SourceOps::read admits StopAsync/CloseAsync inside Frame. I preserved V1 and the alpha-only intermediate, added decode/publication epoch checks and ran the same native facade oracle: the earlier code had two safe failures in 152 checks; V2 passed all 152. I safely return any stale allocated lease in the baseline observer and never dereference freed storage. Separately, my native A8/alpha0 V1 case failed the measured X8 texture-format contract, while all six V2 X8/A8 × alpha0/128/255 cases passed 35 checks each. I include actual SDK2/D3D9 execution in these 210 observations, without certifying complete decoder pixel equivalence, arbitrary screen blending or actual game integration. I retain the earlier four-video/one-muted-DSound 165 checks with their V1 source snapshots; I did not change their default-X8 path through the alpha policy.
